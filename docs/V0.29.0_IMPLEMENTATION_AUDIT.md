# 1. Executive verdict
## Release engineering verdict: **PASS**
The `v0.29.0` artifact is a real, green, provenance-backed release:
- 265 tests pass;
- 52 suites report cleanly;
- zero tests fail, cancel, skip, or remain TODO;
- ESLint passes;
- npm production audit reports zero known vulnerabilities;
- Node 20/22/24 GitHub matrix is green;
- npm publish succeeded with provenance;
- npm `latest` is `0.29.0`;
- no declared third-party runtime dependencies were introduced.
## Architectural acceptance verdict: **REJECT as a conformant implementation of the normative specification**
The release provides a useful prototype foundation, but it implements only a small, shallow subset of the 3,851-line normative specification. The release notes use production-level terms—“interactive onboarding engine,” “stack oracle,” “guided task authoring subsystem,” “declarative preset loader,” “atomic configuration generator”—that materially overstate current behavior.
The implementation should be accepted only as:
> **Experimental wizard primitives and first-pass planning APIs, not a production-ready onboarding/task subsystem.**
## Critical blockers
The following defects are release-blocking for the wizard feature:
1. **`agentctl task create` writes tasks to `.agent/queue/`, while the queue engine consumes `.agent/jules-queue/`.** The CLI says the task is queued, but `agentctl status` reports zero pending tasks and `agentctl queue` will not consume it.
2. **SDK-provided task IDs permit path traversal and arbitrary writes outside the queue directory.** An ID of `../../escaped-task` wrote `<repo>/escaped-task.md`.
3. **`agentctl init` silently overwrites existing `.agent/config.yml` and `.agent/jules.yml` with direct non-atomic writes.** No preview, backup, lock, journal, migration, hash check, or confirmation exists.
4. **Secret preflight can miss a high-confidence token on a later prompt line.** Only one leading `+` is prepended before `scanDiff()`, so subsequent lines are not treated as added lines. Low-entropy padding bypasses the fallback entropy check.
5. **High-confidence secret blocking is explicitly bypassable through the exported SDK with `allowSecrets: true`.** The specification forbids this.
6. **Falsifiability enforcement checks only for a non-empty command string.** “Make the code better” plus `true`, `echo looks-good`, or even a nonexistent command is accepted as dispatchable.
7. **Task Jules flags are comments in a Markdown file, not a canonical envelope consumed by queue dispatch.** `autoPr`, plan approval, repoless mode, source, and starting branch do not survive the queue path.
8. **A normal first-run journey is internally blocked.** `agentctl init` creates uncommitted protected config files; immediate `agentctl task create` runs the working-tree gate and rejects with exit 3.
9. **The TUI library calls `process.exit(130)` from a keypress generator.** This can terminate SDK host processes before raw mode, locks, journals, and outer cleanup complete.
10. **Non-TTY init silently chooses defaults and writes configuration.** This contradicts the normative headless contract, which requires explicit answers or a failure.

```json
}
```

## 4.2 Import graph result: **PASS**

- repository-local modules.
No Inquirer, Chalk, Commander, YAML package, glob package, or other runtime package is introduced.
## 4.3 Runtime-download caveat: **PARTIAL concern**
The Stack Oracle proposes:
```text
npx tsc --noEmit
```
If TypeScript is not installed locally, `npx` may fetch a package at runtime. That undermines the intended offline/zero-supply-chain behavior and can execute an unintended package named `tsc`.
Required correction:
- use the project’s package manager script when present;
- use local `node_modules/.bin/tsc` only when it exists;
- otherwise mark typecheck unavailable;
- never use `npx` as an implicit installer in an inferred oracle.
## 4.4 External tools
Guessing `flake8`, `mypy`, or `golangci-lint` is acceptable only as an unvalidated candidate. The current config promotes them directly without checking installation or receiving user confirmation in all modes. This is a fidelity problem, not a package dependency declaration failure.

# 6. Module A audit — onboarding and Stack Oracle
## 6.1 What is implemented
The release implements:
- root stack detection via existing `detectStack()`;
- root command candidates for test/build;
- supplementary Node, Cargo, Go, and Python guesses;
- basic monorepo flag detection;
- basic pnpm child package discovery;
- a command probe wrapper;
- tier constants;
- four in-memory preset descriptors;
- a minimal custom YAML preset metadata loader;
- a basic interactive tier/test/build/preset flow;
- generated `.agent/config.yml` and `.agent/jules.yml`.
This is a useful skeleton.
## 6.2 Stack Oracle is not a workspace graph
### Polyglot collapse
A repository containing both root `package.json` and Cargo workspace produced:
```json
{
  "stack": "cargo",
  "isMonorepo": false,
  "packages": [],
  "candidates": {
    "testCmd": "cargo test --workspace",
    "buildCmd": "cargo build --workspace",
    "lintCmd": "cargo clippy --workspace -- -D warnings",
    "typecheckCmd": "cargo check --workspace"
  }
}
```
The Node/React side disappears. This fails the explicit Rust-backend + React-frontend requirement.
### Limited monorepo recognition
`isMonorepo` checks only:
```text
turbo.json
pnpm-workspace.yaml
lerna.json
nx.json
```
It does not consider:
- Cargo `[workspace]`;
- `go.work`;
- Maven/Gradle multi-project metadata;
- Elixir umbrella apps;
- CMake/Bazel package topology;
- Docker Compose services;
- multiple unrelated manifests.
### pnpm-only package discovery
Only pnpm workspace files are traversed. The implementation:
- handles simplistic trailing `/*` patterns;
- does not support exclusions/negations robustly;
- uses directory child name instead of `package.json.name`;
- does not attach per-package commands;
- does not build edges or shared triggers;
- follows symlinked package paths via `existsSync`.
### No bounded, evidence-rich detection
The result has no:
- confidence score;
- evidence list;
- manifest inventory per node;
- command provenance;
- validation state;
- dependencies/dependents;
- ownership globs;
- ambiguity warnings.
## 6.3 Candidate quality problems
### Package manager mismatch
Root Node scripts always become npm commands even if pnpm, yarn, or bun lockfiles are present.
### Unverified tool guesses
The oracle proposes:
```text
golangci-lint run
flake8 .
mypy .
npx tsc --noEmit
```
without proving those tools are installed. These are low-confidence candidates but are emitted as configuration values.
### Unknown stack defaults to Node
```js
const stack = detected.stack || "node";
```
An unknown repository can be mislabeled as Node instead of remaining unknown and requiring custom oracles.
### Empty command is reported as a successful probe
Observed:
```json
{
  "ok": true,
  "code": 0,
  "stderr": "Empty oracle command (skipped)"
}
```
An absent oracle must be unavailable, not green.
### Shell-string command model
The specification requires structured executable/args/cwd/timeout/network policy. The implementation stores and runs shell strings through `runCmd()`. Workspace paths and user input are not structurally isolated from command syntax.
## 6.4 Onboarding does not configure Jules
The generated config does not contain:
- API version/base URL;
- API key environment name;
- connected Source resource;
- repository vs repoless mode;
- validated starting/base branch;
- auto-PR default;
- plan approval policy;
- source validation state.
A user can complete onboarding yet still be unable to dispatch without separate undocumented environment setup.
## 6.5 Tier model is not policy-safe
`enterprise` is hard-coded to:
```text
concurrency: 10
daily_tasks: 1000
stagger_ms: 500
diff_kb: 100
```
Problems:
- custom enterprise is not customizable;
- 100 KB violates the normative 75 KB default safety ceiling;
- local policy and provider quota are not distinguished;
- invalid tier names are accepted.
A probe with `tier: "bogus"` emitted `tier: bogus` while silently applying Pro limits.
## 6.6 Interactive tier selection is overwritten
`runInitWizard()` calls:
```js
planInit(root, {
  tier: selectedTier,
  ...options,
});
```
The CLI always passes `tier: values.tier || "pro"`. Because `...options` is last, an interactive user’s menu selection is overwritten by the original Pro value. The tier menu can appear to choose Free or Enterprise while the generated plan remains Pro.
No interactive test catches this.
## 6.7 Oracle probe failure does not block save
When the test probe fails, the spinner displays failure, but the wizard continues and writes the configuration. An invalid command becomes the configured oracle.
## 6.8 Headless init silently writes defaults
In a non-TTY repository, this command:
```bash
agentctl init --json
```
exited 0 and overwrote existing config with:
```yaml
verify:
  test: ""
  build: ""
```
It did so without:
- `--yes`;
- an answers file;
- a dry-run preview;
- a required oracle;
- preserving custom fields;
- warning to stderr.
The normative contract requires a missing-answer failure in this situation.
## 6.9 Existing configuration is destroyed
A pre-existing config containing:
```yaml
version: 99
custom_user_field: keep-me
```
was silently replaced. This is a direct data-loss defect.
## 6.10 “Atomic” write claim is false
`runInitWizard()` calls `writeFileSync()` directly on final paths. There is no:
- temporary sibling file;
- exclusive create;
- fsync;
- atomic rename;
- lock;
- intent journal;
- backup;
- rollback;
- post-write hash/schema verification.
The test named “atomically” checks only file existence and therefore does not test atomicity.
## 6.11 Generated YAML is injectable/malformed
Commands, tier, branch, and preset IDs are interpolated without YAML escaping. A command containing a quote/newline produced malformed/injected YAML:
```yaml
verify:
  test: "echo "quoted"
malicious: true"
```
A preset ID with a newline injected a top-level field.
## 6.12 Config fidelity
The generated config is schema `version: 1`, not `agentctl/config-v3`, and omits nearly all normative fields:
- runner/isolation;
- scope/security;
- workspaces/edges;
- structured commands;
- queue/state/webhook;
- migration/sync manifest;
- provider/source;
- schedule executor;
- ownership.
The generated `jules.yml` contains only test/build commands.
## 6.13 Preset integration in onboarding
Interactive preset choices use `BUILTIN_PRESETS` directly, not `loadPresets()`. Repository custom presets are therefore never shown in the wizard. Selected preset IDs are written to config but no `.agent/presets/*.yml` files or workflow definitions are generated.

# 7. Module B audit — guided task authoring
## 7.1 What is implemented
The release implements:
- non-empty prompt check;
- requirement for one non-empty verification command string;
- known-pattern scan on prompt text;
- whole-prompt entropy check;
- four Jules booleans/branch values in a planning object;
- a standard footer;
- optional TODO selection;
- working-tree gate invocation;
- Markdown task file write;
- CLI and SDK entrypoints.
Again, this is a useful skeleton, but not the specified subsystem.
## 7.2 Queue integration is broken
The engine’s canonical queue directory is:
```text
.agent/jules-queue/
```
Task authoring writes to:
```text
.agent/queue/
```
Black-box result:
```text
Task file: .agent/queue/TASK-MSMDYYVY.md
agentctl status: Pending Tasks 0
```
The CLI prints:
```text
Task synthesized & queued
```
but the task is orphaned. This is the highest-priority functional defect.
## 7.3 Path traversal through task ID
`inputObj.id` is accepted without validation and used in:
```js
join(queueDir, `${plan.taskId}.md`)
```
An exported SDK call with:
```js
id: "../../escaped-task"
```
wrote:
```text
<repository>/escaped-task.md
```
This violates repository containment and permits arbitrary overwrites within reachable paths. Use `randomUUID()` or a strict slug, then verify `resolve(target).startsWith(resolve(queueDir) + sep)` and reject symlinks.
## 7.4 “Falsifiability” is presence-only
The implementation accepts:
```text
Prompt: Make the code better
Verify: true
```
It also accepts:
```text
Verify: echo looks-good
Verify: definitely-not-a-real-command
```
No command is executed by `planTaskCreate()`. The later gate executes configured repository verification, not necessarily `inputObj.verifyCmd`.
There is no:
- current behavior;
- expected behavior;
- acceptance criterion;
- expected exit code;
- evidence model;
- workspace command reference;
- benchmark threshold;
- vague-intent predicate;
- criterion validation.
The test called “unfalsifiable” checks only an empty command.
## 7.5 Interactive default is deliberately vague
The default prompt is:
```text
Cleanly refactor module to improve readability and maintain full test coverage.
```
This is exactly the kind of subjective, unbounded request the normative wizard must refine before dispatch.
## 7.6 Scope governor is absent
No task scope fields exist. The wizard does not collect or validate:
- write allow paths;
- read-only context;
- hard denies;
- protected files;
- workspace ownership;
- active reservations;
- base SHA;
- referenced path existence;
- risk tier;
- maximum files.
It never invokes `validateEnvelope()`.
The working-tree gate runs against the entire repository, not selected task scope.
## 7.7 Gate handling is incomplete
Task creation blocks only codes 3 and 6:
```js
if (!gateRes.ok && (gateRes.code === 3 || gateRes.code === 6)) throw ...
```
It ignores:
- code 5 payload/diff overflow;
- code 4 verification failure;
- code 8 flaky quarantine;
- general gate resolution errors.
A task can be saved after failing the declared verification or exceeding the payload governor.
## 7.8 Init-to-task journey fails
Immediately after init, `.agent/config.yml` and `.agent/jules.yml` are uncommitted protected/denied changes. `task create` runs the working-tree gate and rejects them with exit 3.
Observed:
```text
agentctl init --json       exit 0
agentctl task create ...   exit 1
Gate Preflight Rejected Task ... Exit 3
```
Onboarding does not tell the user to review/commit generated config, and task authoring cannot distinguish wizard-managed changes from malicious scope violations.
## 7.9 Secret scanner misses multiline known tokens
The code calls:
```js
scanDiff(`+${rawPrompt}`)
```
Only the first prompt line begins with `+`. A high-confidence token on line 2 is not scanned as an added line.
A prompt with low-entropy padding plus a valid GitHub-token pattern on line 2 was accepted with zero findings.
Correct approach:
```js
const diffLikePrompt = rawPrompt.split("\n").map((line) => `+${line}`).join("\n");
```
Better: expose a direct text scanner rather than abusing diff semantics.
## 7.10 Secret override violates hard policy
The exported SDK accepts:
```js
allowSecrets: true
```
and returns a valid plan even for a high-confidence AWS secret. High-confidence credential patterns must never be dispatchable through a generic override. Synthetic fixtures require hash-based allow rules and explicit policy.
`allowHighEntropy` creates a second bypass that can expose multiline known tokens due the diff-prefix bug.
## 7.11 Entropy model is not robust
The entropy calculation is over the entire prompt, not bounded token-like substrings. This can:
- miss secrets diluted by repetitive text;
- flag code-rich/high-diversity prose;
- provide no location or fingerprint;
- fail to redact PII;
- fail to scan TODO/issue context separately.
## 7.12 TODO candidate integration is defective
`scanCodebaseForTodos()` returns `tag`, but the wizard reads `type`. Interactive labels and task titles become `undefined`.
The scanner also returns absolute file paths and scans its own/test/generated TODO strings. Candidate text is placed directly into trusted task instructions rather than fenced as untrusted context.
## 7.13 Jules intent is not durable
The task file records booleans only in Markdown comments:
```text
# Auto-PR: true | Plan Approval: true | Repoless: false
```
It omits Source and starting branch. The queue engine reads the entire file as a prompt and creates a task with only title/prompt. It does not parse these comments into:
- `automationMode`;
- `requirePlanApproval`;
- repoless mode;
- Source;
- starting branch.
Even after fixing the queue directory, the author’s Jules choices would not affect dispatch.
## 7.14 No execution envelope
The task artifact has no:
- schema ID;
- front matter;
- base ref/SHA;
- scope;
- criteria;
- limits;
- risk;
- intent/envelope hash;
- source;
- ownership domain.
It is not validated by `validate-envelope.mjs`.
## 7.15 Guardrail footer is not universal
It hard-codes:
```text
package.json
pnpm-lock.yaml
tsconfig.json
.github/
origin main
wc -c
```
This is incorrect for Cargo, Go, Python, CMake, Elixir, Windows, non-main branches, and repoless tasks. It can also conflict with legitimate dependency tasks.
## 7.16 Direct non-atomic task write
Like init, task creation uses direct `writeFileSync` with no lock, journal, temp file, fsync, exclusive create, containment check, or collision retry.
`Date.now().toString(36)` is not collision-resistant for concurrent creators.

# 9. Module D audit — native TUI
## 9.1 Positive foundation
The implementation includes all requested primitive names:
- `select`;
- `multiSelect`;
- `input`;
- `confirm`;
- `secretInput`;
- `spinner`;
- ANSI utilities;
- non-TTY branches.
It uses only native modules and restores cursor/raw mode during ordinary generator completion.
## 9.2 Ctrl+C terminates host process
`readKeypresses()` calls:
```js
process.exit(130)
```
from an exported SDK dependency. `process.exit()` does not guarantee outer `finally` blocks, journal completion, lock release, or stream flush. It may leave the terminal in raw mode despite writing `showCursor` to `process.stdout`.
Required behavior:
- throw `WizardCancelledError` with numeric code 130;
- restore raw state in `finally`;
- let CLI set `process.exitCode` after cleanup;
- never call `process.exit()` in library modules.
## 9.3 Wrong output stream during cancellation
Cancellation writes to `process.stdout` instead of the selected `opts.stdout`. Embedded SDK consumers and JSON mode can be corrupted.
## 9.4 Non-TTY behavior is unsafe
`select`, `multiSelect`, `input`, and `confirm` silently choose defaults and write headless messages. The normative contract requires explicit flags/answers or failure for missing decisions.
`input()` does not run its validator on fallback/default values in non-TTY mode.
This is especially dangerous because `runInitWizard()` uses non-TTY detection to skip questions and write Pro configuration automatically.
## 9.5 JSON stdout contamination
TUI output defaults to `process.stdout`. Interactive `--json` mode will emit ANSI/UI text before the JSON result. UI/progress should use stderr when stdout is machine-readable.
## 9.6 ANSI policy missing
`styleText()` always emits escape sequences. `NO_COLOR=1` still produces ANSI. There is no `TERM=dumb`, output-TTY, or color policy check.
## 9.7 Terminal injection
Option labels, descriptions, prompts, preset names, and manifest-derived values are written without removing control characters. A malicious repository preset/package name can inject ANSI sequences, erase output, spoof selections, or alter terminal title.
Sanitize control characters before rendering.
## 9.8 Key decoding is fragile
The code expects each stream chunk to equal one key sequence exactly. Real terminals may:
- split `ESC [ A` across chunks;
- coalesce multiple keypresses;
- emit alternate application-cursor sequences;
- emit Home/End/Delete variants.
There is no incremental decoder/buffer.
## 9.9 Missing cancellation and navigation
- Escape does not cancel;
- Home/End are unsupported;
- disabled choices unsupported;
- multi-select min/max unsupported;
- empty multi-select options are not rejected;
- select end-of-stream can return `undefined`.
## 9.10 Render/layout robustness
- terminal width is ignored;
- long labels wrap and break `renderedLines` accounting;
- erase loops are likely inconsistent on wrapped lines;
- Unicode display width is not considered;
- redraw writes no explicit line clear per option in the normal movement path.
## 9.11 Secret input
Positive:
- masks typed characters;
- supports backspace;
- does not echo the value on success.
Gaps:
- Ctrl+C process termination issue;
- no validation hook;
- fallback value may be supplied directly and silently;
- cursor/raw cleanup not guaranteed on forced exit;
- value remains a normal JavaScript string with no lifecycle guidance.
## 9.12 Spinner
- timer is not `unref()`’d;
- caller failure before `stop/fail` leaves timer/cursor;
- no wrapper guarantees cleanup;
- non-TTY writes status to stdout;
- no signal integration.
## 9.13 Test gap
All TUI tests use non-TTY `PassThrough` streams. None exercises:
- raw mode;
- arrow keys;
- multi-select toggling;
- Enter confirmation;
- Ctrl+C/Escape;
- stream end/error;
- cursor restoration;
- ANSI disabled behavior;
- long/untrusted labels;
- interactive JSON isolation.
The 45.70% line and 36.17% branch coverage accurately reflects this gap.

# 10. Edge-case and security review
## 10.1 Non-TTY CI degradation — **FAIL**
Expected:
```text
flags / answers JSON / env / existing config / safe validated defaults
missing required decisions -> exit 64
no prompt, no write without --yes
```
Actual:
```text
no TTY -> skip questions -> choose Pro/default presets -> write config -> exit 0
```
There is no:
- `--answers`;
- stdin JSON;
- `--yes`;
- `--dry-run` for init/task;
- `--no-interactive`;
- missing-answer report;
- stable JSON failure schema.
## 10.2 Secret scrubbing — **FAIL**
Confirmed bypasses:
1. later-line known token + low-entropy padding;
2. `allowHighEntropy: true` combined with later-line token;
3. `allowSecrets: true` for high-confidence AWS key;
4. no PII scan;
5. no untrusted-context-specific scan;
6. no generated-prompt rescan;
7. no exact active-environment-value redaction;
8. no value fingerprint/location report.
## 10.3 Monorepo boundary resolution — **FAIL**
The implementation returns one root stack and a shallow pnpm package list. It does not meet the graph, impact routing, ambiguity, per-workspace oracle, shared trigger, or ownership requirements.
## 10.4 Config migration — **FAIL**
No schema migration, sync manifest, managed ownership, three-way merge, backup, or rollback exists. Existing config is overwritten.
## 10.5 Context optimization — **FAIL/absent**
No prompt byte measurement, deduplication, section budget, task split recommendation, context index, policy hash, or anti-truncation metadata exists.
The footer asks for “full terminal verification output,” which may waste context and leak sensitive logs.
## 10.6 Scope and locks — **FAIL/absent**
No task ownership, scope reservation, overlap check, or queue mutex is used. Task creation can race and collide.
## 10.7 Source and Jules v1alpha configuration — **FAIL/absent in wizard**
The wizard does not collect Source, base branch validation, API key environment, auto-PR default, or plan approval policy. Task flags are not dispatchable metadata.

# 13. `v0.29.1` remediation plan

## 13.1 Queue and file safety
1. Use `getQueueDir(root)`; never hard-code `.agent/queue`.
2. Generate IDs with `randomUUID()` plus readable slug.
3. Reject caller IDs not matching a strict pattern.
4. Resolve and verify target containment beneath queue root.
5. Reject symlink queue directories/targets.
6. Use exclusive temp file, fsync, atomic rename, and queue mutex.
7. Add concurrent creator/collision tests.

6. Remove comment-only control metadata.
## 13.3 Secret preflight
1. Add a direct text scanner or prefix every prompt line before `scanDiff()`.
2. Scan prompt, TODO/issue context, generated prompt, and selected diff separately.
3. Remove generic `allowSecrets` for high-confidence findings.
4. Replace whole-prompt entropy with bounded token candidate analysis.
5. Add PII redaction and active-environment exact-value redaction.
6. Return type/location/fingerprint without value.
7. Add multiline, padding, private-key, bypass, and false-positive tests.
## 13.4 Falsifiability
1. Require current behavior, expected behavior, and at least one criterion.
2. Reference configured workspace commands instead of arbitrary shell text by default.
3. Execute/prove task command or resolve an already validated oracle record.
4. Reject subjective patterns unless refined.
5. Block unavailable/nonexistent commands.
6. Treat empty command as `ok:false`.
7. Block save on gate codes 1/3/4/5/6/8 unless saving an explicit non-dispatchable draft.
## 13.5 Init safety
1. Add `--dry-run`, `--yes`, `--answers`, `--no-interactive`.
2. In non-TTY mode, fail on missing required values; never silently write Pro defaults.

8. Make failed probes block or mark commands unverified.
9. Fix option spread order so interactive selections win.

# 16. Final recommendation
## Acceptance decision
**Do not accept `v0.29.0` as a production-ready or specification-complete wizard subsystem.**
Accept it as an **experimental implementation preview** containing:
- native TUI primitives;
- a root stack candidate detector;
- simple onboarding YAML generation;
- simple prompt/task generation;
- initial CLI/SDK wiring.
The release’s strongest achievement is preserving the zero-dependency invariant while establishing module boundaries. Its central weakness is that names and tests imply capabilities that are not yet present. “Atomic,” “falsifiable,” “queued,” “Stack Oracle,” “declarative presets,” and “headless fallback” currently mean much less than the normative specification defines.
## Immediate action
Ship a narrow `v0.29.1` safety patch before promoting these commands:
1. fix queue path;
2. close task ID traversal;
3. remove direct overwrite/non-atomic init behavior;
4. fix secret scanning and remove high-confidence bypass;
5. enforce real criteria and validated oracles;
6. preserve Jules flags in a canonical envelope;
7. correct TUI cancellation and non-TTY policy;
8. add public journey tests.
Then use `v0.30.0` for the complete planning/transaction/schema/workspace/preset architecture.
The implementation is promising, compact, and testable—but it is the first 20–25% of the specified system, not the finished system.
