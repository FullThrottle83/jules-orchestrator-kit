## 1. Token & Truncation Vulnerability Summary

### Answers to the four audit questions

| # | Question | Verdict |
|---|----------|---------|
| 1 | Can downstream LLM prompt injectors break the `JULES_RULES_SENTINEL` checksum verification? | **Yes — by substitution.** The sentinel is an unkeyed SHA-256 integrity tag: any attacker who can replace the *entire* compiled block can wrap their own instructions in a self-consistent sentinel pair, and `verifyRulesSentinel` returns `ok: true` (Appendix A, Exp 1b). In-place truncation/editing/grafting is detected correctly (fail-closed, Exp 1c). The larger hole: **nothing in any production path ever calls `verifyRulesSentinel`** — the checksum is generated by `agentctl rules compile` but verified only by the test suite. |
| 2 | Is the 75 KB payload limit measured in bytes or characters? | **Accurately in bytes** — `Buffer.byteLength(text, "utf-8")` (`src/git.mjs:266-268`). A diff of 10,000 🚀 glyphs (20,000 UTF-16 units) is correctly weighed at 40 KB, not 20 KB (Exp 2a). Binary/non-UTF-8 content is *over*-counted up to ~3× via U+FFFD replacement (conservative, Exp 2b). The genuine defect is on the **prompt side**: the 50 KB cap checks the *raw* `task.prompt` **before** role injection, SPORE hydration and envelope wrapping, so the dispatched payload can silently grow 40%+ past the limit (Exp 2c). |
| 3 | Can complex tasks falsely route to the cheap/fast tier? | **Yes, through four independent doors:** (a) the Declarative Asset Override *defeats the sensitive-path guard* — `.github/workflows/*.yaml` and the orchestrator's own `.agent/jules.yml` route FAST (Exp 3a/3b); (b) explicit `tier: "fast"` in any queue-task envelope is an unauthenticated hard override that skips every heuristic (Exp 3e); (c) complex work phrased without the 15 magic regex keywords scores negative and routes FAST (Exp 3c); (d) trivial-keyword stuffing cancels complex signals (Exp 3f). |
| 4 | Unbounded memory retention in long-running multi-agent swarms? | **Yes.** `readTelemetry(root, limit)` materializes the *entire day's* JSONL corpus (unbounded segment count) into RAM and then slices off `limit` (Exp 4a: asking for 10 events grew heap 85 MB on a 24 MB test day). The dashboard polls that endpoint every 5 s and re-verifies the full hash chain per poll, making it O(day-size) work per request, O(day-size × requests) per shift. |

### Finding roll-up

| ID | Severity | Finding |
|----|----------|---------|
| F-01 | **High** | Sentinel checksum authenticates integrity, not provenance — whole-block substitution verifies clean. |
| F-02 | **High** | `verifyRulesSentinel` is dead code in production; the anti-truncation check is advisory-only and never gates dispatch, CI, or webhook ingestion. |

**Control validation (what the kit gets right):** the diff governor *is* byte-accurate and biased conservative; the git layer fails closed on `ENOBUFS`/timeouts (`src/git.mjs:139-152`); telemetry appends are hash-chained with torn-tail repair and secret scrubbing (`src/telemetry.mjs:57-75, 22-32`); 14-day retention pruning exists (`src/telemetry.mjs:254`); the MCP surface caps telemetry reads at 500 (`src/mcp.mjs:362`); the key decoder buffers at 1 KB (`src/ux/key-decoder.mjs:67`); the log viewer renders only a viewport slice (`src/ux/log-viewer.mjs:73-77`). These patterns are the correct models for the fixes below.

## 2. In-Depth Analysis: Sentinel Cryptography & Budget Linters

### 2.1 What the sentinel actually is

`compileRules` (`src/rules-budget.mjs:84-122`) concatenates rule sources into one body and stamps:

```
<!-- JULES_RULES_SENTINEL BEGIN len=<utf8-bytes> sha256=<hex> -->
<body>
<!-- JULES_RULES_SENTINEL END   len=<utf8-bytes> sha256=<hex> -->
```

- `len` = `Buffer.byteLength(body, "utf-8")` — bytes (`src/rules-budget.mjs:114`).
- `sha256` = SHA-256 of the body string, UTF-8 encoded by Node's crypto (`src/rules-budget.mjs:115`).
- Duplicated in BEGIN and END so a truncated stream loses at least one side of the pair.

`verifyRulesSentinel` (`src/rules-budget.mjs:127-168`) extracts both markers with regexes (`:133-137`), requires BEGIN.len == END.len and BEGIN.sha == END.sha (`:146-147`), slices the body *between* the markers (`:150-152`), recomputes length (`:153`) and hash (`:159-163`).

### 2.2 Cryptographic assessment

1. **It is a checksum, not a signature.** SHA-256 with no key and no externally-pinned reference digest protects against *damage*, never against *authorship*. Anyone able to compute SHA-256 (every LLM, every injector, every CI step) can mint a perfectly valid sentinel pair around arbitrary text. Exp 1b demonstrates this: a fully replaced block ("EVIL: ignore all safety rules...") verifies with `ok: true`. The scheme therefore answers "was this text corrupted in transit?" but can never answer "is this the text we intended?" — which is precisely the property a downstream-LLM-injection defense needs. **Implication:** prompt-injection models that "clean up" a prompt by regenerating rules wholesale will pass verification; models that drop the tail will fail it.

2. **Fail-closed behavior is correct where it applies.** Truncation mid-body, truncating away the END marker, editing one byte, or grafting the original header/footer onto a truncated body all produce errors (test at `test/rules_budget.test.mjs:41-47` + Exp 1c). The duplicate BEGIN/END cross-check also catches the "END eaten by a context window" case, which is the dominant real-world truncation mode.

3. **Regex anchoring defects.** `beginRe.exec`/`endRe.exec` (`:136-137`) search *anywhere* in the string with first-match semantics on non-global regexes:
   - A rules file that merely *documents* the marker format (e.g. a contributor pasting the sentinel format into `docs/*.md` or an example file that lands under `.agent/rules/`) injects an inner END marker; the verifier binds to it and reports a spurious "length mismatch" (Exp 1d). That is a **persistent false-tamper alarm** — and because the alarm text claims injection, operators learn to ignore it, which silently destroys the value of the real signal.
   - Body extraction (`:150-152`) strips exactly **one** leading and one trailing `\n`. Any serializer that normalizes to CRLF, or inserts an extra blank line around the block, shifts the byte count and fails verification — an availability (false-alarm) issue rather than a safety issue, but it will be hit the first time the compiled artifact round-trips through Windows tooling or a YAML serializer.

4. **Unit drift inside one module.** The sentinel measures *bytes* (`:114`) while the linter measures *UTF-16 code units* (`:48`, `content.length`). For BMP-only ASCII prose they coincide; for CJK/emoji rules docs they diverge 3–6× (Exp 1f: 9,999 CJK "characters" = 29,997 bytes and passes the 10,000-char budget). Downstream products' truncation limits are variously documented per characters; tokenizers (byte-fallback BPE) can spend up to 3 tokens per rare glyph, so "< 12k chars" is *not* a token-safety proof for multilingual rule sets. Neither function states its unit in its API.

5. **The budget linter's structural blind spots** (`checkRulesBudget`, `src/rules-budget.mjs:18-72`):
   - **Per-file only — no aggregate.** It audits `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.cursorrules`, `JULES_RULES_TEMPLATE.md` and every `.agent/rules/*.md` individually. But `compileRules` *sums* them. Two files of 9,500 chars each pass every audit and compile to a 19 KB body — past the 12,000-char silent-truncation wall the linter's own messages cite (Exp 1e, and the reason at `:56`).
   - **`else if` masking (`:58`)** — a file violating *both* budgets reports only the char violation; the line violation disappears from output.
   - **Off-by-one line counting (`:49`)** — `content.split("\n").length` counts the phantom element after a trailing newline: a file with exactly 250 real lines and a POSIX-mandated trailing newline is reported as 251 lines and fails (Exp 1g).
   - **Message/threshold drift** — `:61` hardcodes "Claude Code auto-memory truncates > 200 lines" while the enforced default is 250 (`:6`); `:5` cites a 12k Antigravity limit against a 10,000-char default with no safety-factor rationale comment.
   - **Non-deterministic compilation (`:34`, `:90`)** — `readdirSync` results are used unsorted, so section order (and therefore the sentinels' SHA-256) can differ across filesystems for identical content. Any future "pin the expected hash" workflow will produce machine-dependent digests.
   - **Symlink following (`:104-109` + `:173-179`)** — a `.agent/rules/linked.md` symlink to an outside file is happily read into the compiled rules body (Exp 1h). `.agent/rules/**` is BUILTIN_PROTECT (`src/config.mjs:44`), but protection gates the *gate phase*, not the compiler: a one-time allowances or a contributor with merge rights can smuggle arbitrary host-file content into the compiled artifact that agents treat as authoritative.

### 2.3 The wiring gap (the finding that makes the crypto moot)

`verifyRulesSentinel` is referenced *only* by `src/rules-budget.mjs` (definition) and `test/rules_budget.test.mjs` (test). `bin/agentctl.mjs:1941-1956` exposes `rules compile` (which stamps sentinels) but there is **no `rules verify` subcommand**, no CI check, and no consumer in `dispatch`, `run`, `executeQueueDag`, the webhook receiver, or the MCP server. Meanwhile the kit itself never injects the compiled block into dispatched prompts (`src/engine.mjs:866-909` builds prompts from role prompts + SPORE memory + envelope only), so *all* of the "silent instruction loss" this sentinel was designed to catch happens on the consuming side (Antigravity/Claude Code/Jules reading `AGENTS.md` directly) with zero runtime verification on the kit's side. A checksum nobody verifies is indistinguishable from no checksum — **the silent-instruction-loss detector currently cannot make a sound.**

## 3. Edge-Case Failure Scenarios (with file:line references)

> Reproductions are quoted from the actual experiment output in Appendix A. Every scenario was executed against the repo's real modules.

### 3.A Sentinel & rules

**S-1 — Whole-block substitution verifies clean** *(F-01)*
An injector/LLM regenerates the rules block, hashes its own body, stamps a self-consistent sentinel pair. `verifyRulesSentinel` → `{ ok: true }`. References: unkeyed hash at `src/rules-budget.mjs:115,159`; no pinned-digest comparison anywhere in `bin/agentctl.mjs` or `src/engine.mjs`.

**S-2 — Marker-shaped documentation bricks verification** *(F-03)*
Rules file containing the literal string `<!-- JULES_RULES_SENTINEL END len=1 sha256=aaaa…64… -->` (e.g. a `docs/markers.md` that ends up under `.agent/rules/`): first-match END regex (`src/rules-budget.mjs:137`) binds to the inner marker → `length mismatch: BEGIN=294 END=1` → false tamper alarm on every run if verification is ever enforced.

**S-3 — Per-file green, aggregate truncation** *(F-04)*
`AGENTS.md` at 9,500 chars + `CLAUDE.md` at 9,500 chars: `checkRulesBudget` → ok. `compileRules` body → 19,061 chars — silently truncated by downstream tools that cap ~12k. The linter's own violation text acknowledges the wall (`src/rules-budget.mjs:56`) but never sums. Note the kit's own `AGENTS.md` is already 9,903 bytes — 97 bytes under its own default budget — so the aggregate wall is reachable *today* in any consumer that reads both files.

**S-4 — CJK/multilingual rules docs** *(F-05)*
9,999 CJK chars: `.length` = 9,999 → pass; wire size = 29,997 bytes; token cost up to ~3× the ASCII assumption. Byte- and token-safety both silently absent behind a green "char budget". (`src/rules-budget.mjs:48`.)

**S-5 — Exactly-250-line file + trailing newline flagged as 251** *(F-05)*
`content.split("\n").length` phantom element (`src/rules-budget.mjs:49`). Any POSIX-tidy file at the exact boundary fails. Masking: file violating both thresholds reports only chars (`src/rules-budget.mjs:51,58`).

**S-6 — Machine-dependent SHA-256** *(F-05)*
Same rule set, different filesystem dirent order (`readdirSync` unsorted, `src/rules-budget.mjs:34,90`) → different section order → different `sha256`. Cross-machine hash pinning (the only available provenance mechanism today) is broken by design.

**S-7 — Symlink exfiltration at compile time** *(F-05)*
`.agent/rules/linked.md -> /tmp/leaked-secret-file.md`: contents compiled into the rules body and listed in `sources` (`src/rules-budget.mjs:104-110`, `existsSync` helper follows links at `:173-179`).

### 3.B Diff payload governor & prompt caps

**S-8 — Emoji/ideograph-heavy diff** *(control validation)*
10,000 🚀 glyphs: `diffText().length` = 20,125 UTF-16 units, `diffBytes()` = 40,125 bytes. The gate compares bytes ≤ 76,800 (`src/engine.mjs:221-222`; measurement `src/git.mjs:265-268`) — **byte-accurate, correct.** A naive char-based jailbreak does NOT exist here.

**S-9 — Binary/latin-1 untracked file inflation** *(conservative bias)*
10,240 bytes of invalid-UTF-8 in an untracked file (working-tree mode synthesizes the diff by reading it as UTF-8, `src/git.mjs:250-262`) is weighed at 30,806 bytes (~3.0×) from U+FFFD expansion. Safe direction (over-blocks), but it means a legitimate 30 KB protobuf fixture can trip a "75 KB" gate and the operator-facing message (`src/engine.mjs:1074-1075`) reports an inflated KB figure with no explanation. Mitigation is documentation or binary sniffing, not a loosening of the cap.

**S-10 — Post-envelope prompt bloat — the prompt cap measures the wrong artifact** *(F-06)*
`dispatch()` enforces the 50 KB prompt cap at `src/engine.mjs:852-854` on `task.prompt`. After the check, the prompt grows through: role prompt injection (`:873-885`), SPORE hydration `hydratePrompt` (`:890-892`), policy + untrusted-data + learned-remediations via `buildAgentEnvelope` (`:895-903`). Experiment: 51,100-byte prompt passes the check; 71,345 bytes actually dispatched — +20 KB (40%) past the intended ceiling, never re-measured. In a swarm, `buildRepairPrompt` (`src/engine.mjs:786-815`) additionally embeds the *entire* failing stderr (up to the 10 MB `maxBuffer`, `src/git.mjs:19`) into every OODA repair prompt, so a single chatty test runner multiplies provider payloads per attempt.

**S-11 — Config footguns**
`config.limits.diffKb: 0` (intended: unlimited) → `0 || 75` → 75 KB (`src/engine.mjs:221`). `diffKb: "abc"` → NaN → every diff over-blocks silently. Same `||` pattern for `promptKb` (`:852`) and the trust-root `limits` fallthroughs in `src/config.mjs:468-469`.

### 3.C Router complexity classifier

**S-12 — CI workflow YAML routed to the cheapest tier** *(F-07)*
Task on `.github/workflows/deploy.yaml`: sensitive pattern `.github/**` matches (`src/router.mjs:87`), but `.yaml ∈ DECLARATIVE_ASSET_EXTS` (`:24-34`) makes `isAllDeclarative` true, so the forced-complex branch at `:142-148` is skipped, and the explicit FAST branch at `:169-173` fires: `tier=fast, score=-3`. Cheap-tier edits to GitHub Actions = supply-chain surface (workflow files run with repo secrets). Experiment 3a confirms.

**S-13 — The orchestrator's own trust config routed FAST** *(F-07)*
`.agent/jules.yml` is in `SENSITIVE_PATH_PATTERNS` (`src/router.mjs:90`) and in `BUILTIN_DENY` (`src/config.mjs:31-41`) — yet `.yml` makes it "declarative", so the cheap tier can author the scope/verify/limits definitions every later gate trusts. Experiment 3b confirms.

**S-14 — Unauthenticated hard override** *(F-08)*
`task.tier === "fast"` returns `forced: true` immediately (`src/router.mjs:126-129`) before role guards and path guards. Tier fields flow in from `JULES_TASK_ENVELOPE` comment metadata (`src/dag-engine.mjs:506`) and raw JSON task files (`:519`) into `dispatch` (`:553`), and from the wizard (`src/wizard-task.mjs:216`) — i.e. any automation or contributor that can author a queue file pins the provider tier. Experiment 3e: an auth-schema-breaking-change refactor routes FAST, `forced=true`.

**S-15 — No-magic-word complex work** *(F-09)*
"Make the login flow faster and fix the race when user sessions refresh token expiry" → score −1 → FAST. Session/JWT/OAuth/CSRF/idempotency/migration-adjacent work that never says `auth|schema|database|refactor` has no signal at all (`src/router.mjs:53-69`). Experiment 3c.

**S-16 — Keyword washing** *(F-09)*
Six complex signals (+12) in one prompt are out-voted by stuffed trivial vocabulary (−13 max from 13 uncapped −1 patterns, `src/router.mjs:41-51,186-198`), plus mechanical title prefix (−2, `:184`), a FAST-leaning role such as `janitor` (−2, `:220-222`), single-file (−1) and short-prompt (−1) freebies. Experiment 3f: `score=-5 → FAST` on a prompt whose stated substance is "refactor migration of the architecture schema for the database with concurrency fix". Conversely a neutral/empty prompt scores 0 → `score > 0` false → FAST: the tie-break biases to cheap, not to quality (`:229`).

**S-17 — Saturation guard measures the wrong root, and unmeasurable files vanish** *(F-10)*
`existsSync(file)`/`statSync(file)` at `src/router.mjs:153-157` resolve against `process.cwd()`, not `config._root`/task root. In swarm worktrees, from a different CWD, with `file.mjs:42` line-suffix tokens, or for to-be-created target files, the byte total is 0 and `MAX_FLASH_BYTES` (24 KB, `:36`) never fires. The prompt path-token extractor (`src/task-optimizer.mjs:57-75`) additionally splits on whitespace, so quoted paths containing spaces evade both guards entirely. Unknown sizes must fail toward COMPLEX, not toward FAST-by-omission.

### 3.D Telemetry & log viewer memory

**S-18 — `readTelemetry` materializes the whole day for a tail** *(F-11)*
`src/telemetry.mjs:293-322`: loops all segments, `readFileSync` each fully, `JSON.parse` + `Object.freeze` every record into `allEntries`, then `return allEntries.slice(allEntries.length - limit)`. Segments per day are unbounded (rotation only caps each at 8 MB, `:19,191-201`). Exp 4a: `readTelemetry(root, 10)` → +85.4 MB heap on a 24 MB/30k-record day. Under a real multi-agent swarm day (gate phases, router decisions, OODA attempts — each tens of events per task at 8 MB ceilings), a single `agentctl status` can transiently allocate gigabytes.

**S-19 — Dashboard amplification loop** *(F-11)*
`src/dashboard.mjs` — the page polls `/api/telemetry` every 5 s (`:63,79`); each request calls `verifyTelemetryIntegrity` (full-day rescan + rehash, `src/telemetry.mjs:330-407`) **and** `readTelemetry` (full-day read) (`src/dashboard.mjs:106-107`). Quadratic I/O per day; and unlike the MCP surface (`src/mcp.mjs:362` caps at 500), the HTTP `limit` parameter is uncapped (`src/dashboard.mjs:100`).

**S-20 — Byte-unbounded buffers around the swarms** *(F-12)*
- Dev-server probe: `stdoutLogs += chunk` / `stderrLogs += chunk` for the full probe window (`src/engine.mjs:1152-1162`), `.slice(-2000)` applied only when formatting the return — a hot-reload loop can print tens of MB inside 15 s.
- `ProgressBus.sendFrame` pushes into `this.queue` unconditionally (`src/mcp-progress.mjs:50-56`); a blocked output stream (paused TTY, closed pipe consumer) grows the queue without a high-water mark.
- `withVfsMutex` contention path busy-spins `while (Date.now() < deadline) {}` (`src/state.mjs:221-222`) — every `appendTelemetry` call from 4+ concurrent swarm slots burns a full core while serializing the event loop.
- `src/ux/log-viewer.mjs` *renders* only a viewport slice (`:73-77`) — correct — but its `LogDocument.lines` contract has no bound and the viewer is currently exercised only by tests, so the first production caller owns the whole transcript in memory. Document the bound in the type (fix below).

## 4. Actionable Improvements (ready-to-use code)

### R-01 — Give the sentinel provenance: keyed MAC + pinned digest + anchored parse

Replace bare SHA-256 with an HMAC keyed from an operator-controlled secret (env var, never committed), and anchor the markers to the exact edges of the artifact. When no key is available, fall back to a pinned digest recorded in `.agent/state/rules-head.json` and compare *to that*, not merely to internal consistency.

```js
// src/rules-budget.mjs — PATCH SKETCH
import { createHash, createHmac } from "node:crypto";

export function computeRulesMac(body, key) {
  return key
    ? createHmac("sha256", key).update(body, "utf-8").digest("hex")
    : createHash("sha256").update(body, "utf-8").digest("hex");
}

export function compileRules(root = process.cwd(), opts = {}) {
  // ...existing body assembly, BUT: const files = readdirSync(rulesDir).sort();
  const key = opts.macKey ?? process.env.JULES_RULES_MAC_KEY ?? null;
  const tag = computeRulesMac(body, key);
  const header = `<!-- ${SENTINEL_BEGIN} len=${bodyLen} sha256=${tag} -->`;
  const footer = `<!-- ${SENTINEL_END} len=${bodyLen} sha256=${tag} -->`;
  // ...unchanged
}

export function verifyRulesSentinel(compiled, opts = {}) {
  // Reject marker literals inside the body: there must be EXACTLY ONE begin
  // and ONE end, at the edges — anything else is an injection by construction.
  const beginRe = /^\s*<!--\s*JULES_RULES_SENTINEL\s+BEGIN\s+len=(\d+)\s+sha256=([0-9a-f]{64})\s*-->\r?\n/;
  const endRe   = /\r?\n<!--\s*JULES_RULES_SENTINEL\s+END\s+len=(\d+)\s+sha256=([0-9a-f]{64})\s*-->\s*$/;
  const beginMatch = beginRe.exec(compiled);
  const endMatch = endRe.exec(compiled);
  if (!beginMatch || !endMatch) return { ok: false, errors: ["sentinels must anchor the artifact edges"] };

  const [declaredLen, declaredTag] = [Number(beginMatch[1]), beginMatch[2]];
  if (declaredLen !== Number(endMatch[1]) || declaredTag !== endMatch[2]) {
    return { ok: false, errors: ["BEGIN/END sentinel metadata mismatch"] };
  }

  const body = compiled.slice(beginMatch[0].length, endMatch.index);
  if (/JULES_RULES_SENTINEL (BEGIN|END)/.test(body)) {
    return { ok: false, errors: ["forged marker embedded inside body"] };
  }
  if (Buffer.byteLength(body, "utf-8") !== declaredLen) {
    return { ok: false, errors: [`body length mismatch: truncation or injection`] };
  }
  const ok = computeRulesMac(body, opts.macKey ?? process.env.JULES_RULES_MAC_KEY ?? null) === declaredTag;
  if (!ok) return { ok: false, errors: ["tag mismatch: content tampered or wrong key"] };

  // Provenance pin: compare to the digest recorded at compile time.
  if (opts.expectedSha256 && declaredTag !== opts.expectedSha256) {
    return { ok: false, errors: ["compiled body does not match the pinned digest"] };
  }
  return { ok: true, errors: [], bodyLen: declaredLen, sha256: declaredTag };
}
```

Also: sort `readdirSync` results (`.sort()` at `src/rules-budget.mjs:34` and `:90`), reject symlinks in `.agent/rules/` (`statSync` → `lstatSync` + `isSymbolicLink()` check), and XML-escape or reject rule files containing the sentinel literal at compile time.

### R-02 — Add the missing aggregate budget + fix the linter off-by-ones

```js
// src/rules-budget.mjs — add to checkRulesBudget():
const COMPILED_MAX_CHARS = 11000;          // below the cited 12,000 silent-truncation wall
export function checkRulesBudget(root = process.cwd(), opts = {}) {
  const res = { ok: true, violations: [] };
  // ...existing per-file loop, with two fixes:
  //   lineCount = content.endsWith("\n") ? content.split("\n").length - 1
  //                                     : content.split("\n").length;
  //   drop the `else` between char and line checks so both are reported.

  // Aggregate check against the SAME units the sentinel uses (bytes):
  const { body } = compileRules(root);
  const bodyLen = Buffer.byteLength(body, "utf-8");
  const compiledMax = opts.maxCompiledBytes ?? COMPILED_MAX_CHARS;
  if (bodyLen > compiledMax) {
    res.violations.push({
      path: "<compiled-aggregate>",
      charCount: body.length, lineCount: body.split("\n").length,
      reason: `Compiled rules body is ${bodyLen} bytes across all sources; exceeds compiled budget ${compiledMax}. Per-file budgets cannot prevent aggregate truncation.`,
    });
  }
  res.ok = res.violations.length === 0;
  return res;
}
```

### R-07 — Telemetry: stream the tail instead of materializing the day

```js
// src/telemetry.mjs — drop-in bounded readTelemetry():
import { openSync, readSync, closeSync, statSync } from "node:fs";

export function readTelemetry(rootOrOpts = resolveRoot(), limit = 50, targetDateStr = null) {
  const root = typeof rootOrOpts === "string" ? rootOrOpts : resolveRoot();
  const stateDir = getStateDir(root);
  const dateStr = targetDateStr || new Date().toISOString().split("T")[0];
  const segments = getTelemetrySegmentFiles(stateDir, dateStr);
  const out = [];
  const CHUNK = 64 * 1024;

  for (let s = segments.length - 1; s >= 0 && out.length < limit; s--) {
    const path = segments[s].path;
    if (!existsSync(path)) continue;
    const size = statSync(path).size;
    let carry = "";
    for (let pos = size; pos > 0 && out.length < limit; ) {
      const readSize = Math.min(CHUNK, pos);
      pos -= readSize;
      const fd = openSync(path, "r");
      const buf = Buffer.alloc(readSize);
      try { readSync(fd, buf, 0, readSize, pos); } finally { closeSync(fd); }
      carry = buf.toString("utf-8") + carry;
      const lines = carry.split("\n");
      carry = lines.shift();                        // possible partial line, keep walking
      for (let i = lines.length - 1; i >= 0 && out.length < limit; i--) {
        if (!lines[i]) continue;
        try { out.push(Object.freeze(JSON.parse(lines[i]))); } catch (_) {}
      }
    }
    if (carry && out.length < limit) {              // first line of segment had no leading \n
      try { out.push(Object.freeze(JSON.parse(carry))); } catch (_) {}
    }
  }
  return out.reverse();                             // chronological, bounded by `limit`
}
```
