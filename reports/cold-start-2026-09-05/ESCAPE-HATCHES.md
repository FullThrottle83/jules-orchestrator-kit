# Phase 5 — escape hatches and trust boundaries

This is an inventory, not a claim that every provider, network, and SDK path was dynamically covered. “Exercised” means real CLI runs in fresh target directories. Full commands, results, and source-search captures are in the evidence archive (`phase5-*`, `escape-hatches-source.txt`, `escape-hatches-env.txt`). All substantive dynamic cases were repeated twice.

## Exercised gate controls

| Control | Does it do only what its name suggests? | Visibility and authority |
|---|---|---|
| `--allow-protected` | A documentation-only go.mod edit changed from scope exit 3 to approval. A subsequently added denied `.key` path still failed. It did not disable the native suite. | Human CLI banner present. The JSON result lacked equivalent waiver provenance. A protected config diff can be authorized by this broad flag, so do not give an agent an uncontrolled invocation. |
| `JULES_ALLOW_COMMAND_FILE_CHANGES=true` | Same protection bypass as the CLI flag in the tested case. | No human override banner. `AGENT_ALLOW_COMMAND_FILE_CHANGES=true` also worked without a banner. F18. These are invocation environment controls, not ordinary YAML keys. |
| `--allow-test-change removal` | Specific deletion changed from exit 6 to approval. Adding a separate skip still failed. | Correct human override banner. Changing the flag requires control of the invocation, not merely the repository diff. |
| `--allow-test-change skip` | The explicit pytest skip changed from exit 6 to approval. | Correct human banner. Native suite still ran the remaining tests. |
| `--allow-test-change commented` | Added commented assertion changed from exit 6 to approval. A separate skip still failed. | Correct human banner. A real removal caused by commenting out an existing assertion may need an additional removal waiver; allowing one kind is not permission for all other consequences. |
| `--allow-test-change vacuous` | A recognized `assert(True)` call changed from exit 6 to approval. Separate skip still failed. | Correct human banner. An initial bare `assert True` addition did not isolate this guard kind and was replaced with the recognized-call control; it was not counted as a failed waiver. |
| `--allow-test-change weakening` | Specific equality replaced with a type assertion changed from exit 6 to approval. A separate skip still failed. | Correct human banner. |
| `--allow-test-change expectation` | The Go literal expectation rewrite over deliberately broken production code changed from exit 6 to approval. A separate skip still failed. | Correct human banner. An initial equivalent Python `value + 0` edit was a negative control, not proof of this flag doing work; the Go positive control replaced it. |
| `--allow-test-change deregistration` | Removing precisely the `test_` prefix from Python `test_int_bytes` changed from exit 6 to approval. An unrelated skip still failed. | Correct human banner. Replacing `test_` with `check_` escaped even the strict guard; F04 is that separate defect. |
| `--allow-test-change all` | All tested deletion/skip findings were waived. | Banner named the supplied `all` waiver. This is intentionally broad. |
| `--allow-test-modifications` | All tested deletion/skip findings were waived. | Human banner said every tamper check was waived. It also suppresses the post-run integrity-lock enforcement in the inspected engine; a separate mid-run mutation scenario was not executed. |
| Unknown allow kind | `does-not-exist` did not turn the failing deletion/skip run green; exit remained 6. | It did not silently become `all`. No assertion is made that exit 6 is ideal argument-validation UX. |
| `--allow-unreadable-tests` | A real executed Python assertion facade (`ensure(...)`) went from unreadable-dialect rejection to approval; a recognized skip still failed. | CLI banner present, plus a diagnostic saying the dialect was not checked. |
| `verify.tamperGuard: warn` / `tamper_guard` | Camel-case committed config allowed the unreadable facade, not an ordinary recognized skip. Snake-case support was found in the trusted-field loader, not independently executed. | The unreadable warning disclosed the config waiver even though the general banner was absent. It is not a switch for every tamper rule. |
| `verify.required: false` | Does **not** skip already configured commands. It relaxes the missing/empty-oracle requirement; a failing Go command still caused exit 4. | Banner incorrectly says nothing is executed. F19. A direct uncommitted edit remained scope-rejected against HEAD. |
| `verify.minTests: 0` / `min_tests` | Camel-case committed config disabled the test-count floor; an empty-selection command approved a production break. Snake-case loader support was inspected, not separately executed. | No waiver banner. F18 concerns the visibility of this intentional opt-out. F09 separately shows an empty Go selection passing even with the default floor. |
| `verify.profile: minimal` | Removed the extra stage pipeline, but did **not** bypass the tamper scan in the security phase: deletion still failed. | `profile` command shows the stage list. The gate output itself does not name the selected profile. |
| `verify.profile: max` | Added mutation and stability. Go reported why V8 coverage was skipped; its untested-file case still approved. Node max rejected the arithmetic-file case through mutation. | Profile output disclosed skipped unsupported stages. Do not generalize the Go false green into a claim that Node max also failed. |
| `verify.stages[].required: false` | A failing test stage became advisory and the overall gate approved. | No visible waiver/failure marker in the human approval. F18 treats this authorized relaxation as a provenance/output defect, not an unauthorized bypass. |
| `verify.stages`, profile expansion, `test` command overrides | Protected direct config edits failed normally. However, bootstrap, staged-mode live-config fallback, and self-selected base allowed an agent to supply its own effective stage plan. | F06–F08 are severity 1 authority failures. Knowing a command string from the base is insufficient when the executable stage array comes from somewhere else. |
| `base_branch` / `baseBranch`; CLI `--base` | CLI base selection worked. A committed agent edit setting `base_branch: HEAD` chose its own trust anchor. | The base is printed, but that does not make its source trustworthy. F08. Snake-case config spelling was the exercised one. |
| `--mode staged`, `--mode committed`, `--mode working-tree` | Changed the diff under review, but not the working copy used by the test command. | F10: staging/committing broken code and restoring only the working copy produced approval. Mode is visibly labeled; the verification-input mismatch is not. |
| `evidence.enabled: false` | Set in committed config, but the gate still generated manifests. | Two before/after inventories demonstrate this ignored output-control setting. Same output-control class as F20, severity 3; not evidence that the native verification was skipped. |
| `evidence.strictTestLock: false` / `strict_test_lock` | Accepted as config; loader and engine consumer inspected. No dedicated mid-run test-rewrite attack was performed for this key. | No general override banner. Do not treat the clean-run probe as complete proof of lock semantics. |
| `check --dry-run` | Still generated evidence files, despite help promising otherwise. | F20. This differs from correctly labeled, non-dispatching `dispatch --dry-run`. |
| `--strict-locks` | Does not work: the parser rejects the flag advertised by gate help. | F17, severity 2 on a healthy invocation. |

## Other controls found, not fully characterized dynamically

These are why phase 5 is marked partial rather than claiming every check-disabling interface was proven.

| Surface | Keys/flags and relevance | Limit of this trial |
|---|---|---|
| Standalone thresholds | `mutate --min-score`, `--max-mutants`; `coverage --min`; probe repeat/pass-rate controls; perf maximum-delay controls | Mutation and coverage were run at defaults; not every zero, negative, or low-threshold edge was tested. Lower thresholds and fewer repetitions can weaken confidence. |
| Declarative assertions | Stage `minScore`, `maxMutants`, `minCoverage`, stability repetitions/pass rate, file/glob targets, pattern/budget limits; stage inclusion/omission and `required` | Inspected via installed implementation and help; not every assertion type/threshold combination was invoked. Mutator and coverage evidence exist; size/pattern/performance contracts are not independently audited here. |
| Pipeline commands | `verify.setup/lint/test/unit/fuzz/invariant/e2e/build/teardown`, legacy `*_cmd`, explicit `stages`, stage `kind`, `cmd`, and stage timeouts | Empty/missing test commands, configured no-ops, optional failing stages, and replaced wrappers were exercised. Every legacy alias, stage-kind mislabel, lifecycle hook, and timeout edge was not. A hand-written stage list replaces profile expansion. |
| Scope | `scope.allow`, `scope.deny`, `scope.protect`, legacy allow/forbidden paths and command manifests | Ordinary protect/deny interaction was exercised. No comprehensive path-normalization/symlink/Windows attack corpus. Direct policy edits were protected; trust-source bypasses were proved separately. |
| Verification scope | `verify.scope: affected/global` | A working real monorepo baseline was blocked by dependencies, so actual affected-package coverage/fallback was not verified. |
| Network policy | `verify.policy.offline`, `networkAccess`, stage `networkAccess`; `JULES_SANDBOX_OFFLINE` and aliases | No controlled egress test. The implementation injects a Node preload; this trial does not establish OS-wide isolation of Go/Rust/Python or external binaries. |
| Evidence configuration | Strict-lock and output enable switches above; evidence manifest assertion inputs | Normal generate/show/verify succeeded. Digest verification was not misrepresented as a signature or proof that the working source was tested. |
| Payload/budget/governors | `limits.diffKb/diff_kb`, prompt limits, daily tasks, repair attempts/concurrency, tier selection, environment overrides | The compact lockfile probe isolates scope from size. Full quota and payload boundary suites not run; no paid tasks dispatched. |
| PR harvesting | `pr harvest --allow-no-checks`, risk/tier filters, `--auto`, `--dry-run` | Advertised/inventoried, not exercised against a real mergeable remote PR. No remote mutation was authorized. |
| Dispatch/task controls | Plan approval selection, `--repoless`, optional `--check-premise`, dry-run, provider selection | No-credentials and dry paths tested. Live execution, premise short-circuiting, hosted plan enforcement, and repoless agent safety unverified. |
| SDK-only inputs | `allowUnverifiable`, `allowHighEntropy`, `allowSecrets`, `skipPreflight`, programmatic guard waiver options, test-predicate injection | Found in installed source; these are not falsely presented as public YAML keys or accepted CLI flags. No complete SDK authority-boundary audit. |
| Additional environment aliases | `AGENT_*` → `JULES_*`, including rule-change allowance and mode/dry-run spellings | Command-file waiver alias exercised. Remaining aliases were inventoried, not all behavior-tested; the full capture is in the archive. |

## What held

The narrow waiver controls generally did what they should: allowing one recognized tamper kind did not allow an unrelated skip. `--allow-protected` did not bypass a denied path. Direct config edits against the committed installed policy were rejected. Missing-provider failures were clear. These controls are useful; the authority and snapshot failures show why they cannot yet be relied on as the whole gate.
